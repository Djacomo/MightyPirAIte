## What this skill does

Scans your existing HTML/CSS for recurring visual patterns, extracts a reusable component
library with design tokens, and applies it incrementally across the project — without
big-bang rewrites and without breaking existing JS hooks or data attributes.

## When to use it

- Your CSS works but has no structure — copy-pasted values scattered everywhere
- You want visual consistency across views without rewriting everything from scratch
- You are a backend or infrastructure engineer who needs clean, maintainable frontend code
- You are inheriting a codebase with no design system and need to introduce one gradually

## When NOT to use it

- Your project already has a design system (Tailwind config, CSS variables, token file) —
  use a refactor skill for that specific system instead
- You need to migrate to a CSS framework (Bootstrap → Tailwind, etc.) —
  this skill extracts from what you have, it does not migrate stacks
- Your HTML/CSS is generated by a framework's build step and not hand-editable

## Invoke

```
/ui-components-refactor
```

## Input

- An open project in Claude Code's working directory
- At least one HTML file and one CSS file (or inline styles)
- No specific setup required — the skill reads your existing files

## What it does — step by step

1. **Asks scope** — single view, a set of views, or the whole project
2. **Scans HTML/CSS** for recurring visual patterns:
   buttons, cards, tables, badges, inputs, headings, layouts
3. **Proposes a design token set** mapped from your existing values:
   colors, spacing scale, typography, border radius, shadows
4. **Defines a component API** for each identified pattern:
   name, props, variants, and token dependencies
5. **Produces an incremental refactor plan** — small, reviewable diffs, one batch at a time
6. **Applies changes batch by batch**, preserving all JS event hooks and data attributes

Each step pauses for your review before proceeding.
Nothing is applied without your explicit confirmation.

## Output

- A `design-tokens.css` file (or equivalent) with all extracted CSS variables
- Refactored HTML/CSS files with components replacing inline repetition
- A summary of every component defined, with its variants and token usage

## Example

**Before:**
```css
.btn-primary { background: #1a73e8; color: #fff; padding: 8px 16px; border-radius: 4px; }
.cta-button  { background: #1a73e8; color: white;  padding: 8px 16px; border-radius: 4px; }
.save-btn    { background: #1a73e8; color: #fff;   padding: 8px 16px; border-radius: 4px; }
```

**After:**
```css
/* design-tokens.css */
:root {
  --color-primary: #1a73e8;
  --color-on-primary: #fff;
  --spacing-btn-v: 8px;
  --spacing-btn-h: 16px;
  --radius-btn: 4px;
}

/* components/button.css */
.btn {
  background: var(--color-primary);
  color: var(--color-on-primary);
  padding: var(--spacing-btn-v) var(--spacing-btn-h);
  border-radius: var(--radius-btn);
}
```
